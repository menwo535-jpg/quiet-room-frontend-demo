01 / CSV import & review

A matched subtotal is not a complete quotation

A small CSV review tool becomes more useful when it makes uncertainty visible instead of hiding it behind a neat number.

14 October 2026 · Independent Draftdesk example

Start with the business decision

In Draftdesk, a request CSV contains product codes, descriptions, quantities and units. A catalogue CSV supplies prices, currencies and a price version. The task is to compare them and show which lines are ready for a person to review. It is not an approval system.

The original synthetic sample has six request lines. Two match, producing a USD 32.50 subtotal. Four need review: an unknown product code, a unit mismatch, a zero quantity and a catalogue code with two competing prices. Showing USD 32.50 as the quote total would conceal most of the request.

Keep the exception attached to its source

Each result keeps its original line number, code, quantity and unit alongside the reason for review. A mismatched unit is not silently converted. In the sample, changing BOX to EA is an explicit user edit; the tool then compares the inputs again. Fixing one row does not mean the remaining exceptions have disappeared.

The cleaned fixture produces five matched lines and USD 90.80. This is a second, deliberately corrected set of inputs. It does not show that the application inferred the missing facts, and even a fully matched result still needs human approval.

Reproduce both results

Download the dependency-free core module into the example path below. Save this snippet as an .mjs file at the site root, then run it with Node.js. It uses synthetic constants and makes no network requests.

import { reconcile, SAMPLE_REQUEST, SAMPLE_CATALOGUE,
  CLEAN_REQUEST, CLEAN_CATALOGUE } from './examples/draftdesk/core.mjs';

const original = reconcile(SAMPLE_REQUEST, SAMPLE_CATALOGUE);
console.log(original.reviewCount, original.complete, original.subtotals);
// 4 false { USD: '32.50' }

const corrected = reconcile(CLEAN_REQUEST, CLEAN_CATALOGUE);
console.log(corrected.reviewCount, corrected.complete, corrected.subtotals);
// 0 true { USD: '90.80' }

Parsing and money need separate rules

A comma in a quoted description is not a new column. The parser handles quoted commas, quoted newlines, escaped quotes, a byte-order mark, CRLF and reordered required headers. It rejects malformed quoting, duplicate headers and inconsistent field counts before comparing business values. This preview limits each file to 1,000 rows and 700 KB.

Prices and quantities use fixed-scale BigInt arithmetic rather than binary floating-point addition. Each line rounds half up to cents. Separate currencies remain separate subtotals; the program does not invent an exchange rate. Formula-prefix escaping applies to spreadsheet exports, while source editing preserves the underlying product identifiers.

What this check establishes

The existing 14 core tests passed again on 14 October 2026. They cover the sample, corrected inputs, CSV boundaries, decimal rounding, duplicate handling, currency separation, export escaping and row editing. Run the test file beside the core with node --test examples/draftdesk/test_core.mjs.
